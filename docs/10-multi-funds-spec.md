# אפיון: מערכת מספר קופות/קרנות גמ"ח

## סקירה כללית

### רקע
מערכת הגמ"ח הנוכחית מנהלת את כל ההלוואות והכספים כקופה אחת. ישנם גמ"חים שמנהלים מספר קרנות או קופות נפרדות, כל אחת עם מטרה ייעודית ויתרה נפרדת.

### דוגמאות לשימוש
- **גמ"ח עם קופה להלוואות עומדות וקופה נוספת להלוואות עם פרעון חודשי**
- **גמ"ח עם קרן הלוואות לחתונה, קרן הלוואות לצרכי רפואה, וקרן הלוואות כללית**
- **גמ"ח עם קופה עיקרית וקופה ייעודית למצבי חירום**

### מטרה
להוסיף תמיכה בניהול מספר קופות/קרנות במערכת, כאשר:
- כל הלוואה משוייכת לקופה מסוימת
- כל קופה מציגה יתרה נפרדת
- ניתן לראות דוח כולל וגם דוחות לפי קופה

---

## דרישות תפקודיות

### 1. ניהול קופות (Funds Management)
- **הוספת קופה חדשה** - שם, תיאור, האם קופת ברירת מחדל
- **עריכת קופה קיימת** - שם, תיאור, סטטוס (פעילה/לא פעילה)
- **מחיקת קופה** - רק אם אין לה הלוואות משוייכות
- **קופת ברירת מחדל** - חייבת להיות תמיד לפחות קופה אחת מוגדרת כברירת מחדל

### 2. שיוך הלוואות לקופות
- בעת יצירת הלוואה חדשה - בחירת קופה מרשימה נפתחת
- אם לא נבחרה קופה - שיוך אוטומטי לקופת ברירת המחדל
- הלוואות קיימות (לפני הפיצ'ר) - יוקצו אוטומטית לקופת ברירת מחדל במהלך המיגרציה

### 3. תצוגת יתרות
- **Dashboard הראשי**:
  - יתרה כוללת של כל הקופות ביחד
  - פירוט יתרה לפי קופה (כרטיסים/טבלה)
  
- **דוח מפורט לפי קופה**:
  - סה"כ הלוואות בקופה
  - סה"כ יתרת חוב בקופה
  - סה"כ כסף זמין בקופה (תרומות + הפקדות - הלוואות)

### 4. סינון וחיפוש
- **במסך הלוואות** - אפשרות לסנן לפי קופה
- **בדוחות** - אפשרות לראות דוח לפי קופה ספציפית או כל הקופות

## שינויי מודל נתונים (Database Schema)

### טבלה חדשה: `funds` (קופות)

```typescript
interface Fund {
  id: string              // UUID - מזהה ייחודי
  name: string            // שם הקופה (למשל: "קרן חתונות", "קרן רפואה")
  description?: string    // תיאור אופציונלי
  is_default: boolean     // האם זו קופת ברירת המחדל
  is_active: boolean      // האם הקופה פעילה (false = מושבתת)
  created_at: string      // תאריך יצירה
  is_deleted?: boolean    // soft delete
  deleted_at?: string     // מתי נמחק
}
```

### שינויים בטבלאות קיימות

הוספת שדה `fund_id` (NOT NULL לאחר מיגרציה) ל:

**1. `loans` (הלוואות)**
```typescript
fund_id: string  // UUID - foreign key לטבלת funds
```

**2. `donations` (תרומות)**
```typescript
fund_id: string  // UUID - foreign key לטבלת funds
```

**3. `deposits` (הפקדות)**
```typescript
fund_id: string  // UUID - foreign key לטבלת funds
```

**4. `expenses` (הוצאות)**
```typescript
fund_id: string  // UUID - foreign key לטבלת funds
```

**הערה**: פירעונות (`repayments`) לא צריכים שדה זה - הם יורשים את `fund_id` מההלוואה שלהם.

### מיגרציה

**חובה לפני מיגרציה**:
1. **גיבוי אוטומטי** - שימוש ב-`fullBackupService.createBackup()` הקיים
2. **בדיקת אידמפוטנטיות** - שמירת דגל `funds_migration_v1_completed` ב-localStorage

**צעדי המיגרציה**:
1. יצירת קופת ברירת מחדל (אם אין)
2. UPDATE אחד לכל טבלה (לא לולאה!):
   ```sql
   UPDATE loans SET fund_id = '<default_fund_id>' WHERE fund_id IS NULL
   UPDATE donations SET fund_id = '<default_fund_id>' WHERE fund_id IS NULL
   UPDATE deposits SET fund_id = '<default_fund_id>' WHERE fund_id IS NULL
   UPDATE expenses SET fund_id = '<default_fund_id>' WHERE fund_id IS NULL
   ```
3. `commitData()` - שמירת כל השינויים
4. הוספת אינדקס: `CREATE INDEX idx_loans_fund_id ON loans(fund_id)` (וכן לשאר הטבלאות)

**טיפול בייבוא גיבוי ישן**:
- `fullBackupService.importFullBackupZip()` חייב לזהות חוסר טבלת `funds`
- להריץ את אותה מיגרציה על הנתונים המיובאים
- לוודא שכל הרשומות מקבלות `fund_id` של קופת ברירת המחדל

**בדיקה אוטומטית** (vitest):
- בדיקה שגיבוי ישן ללא `funds` עובר מיגרציה בהצלחה
- בדיקה שכל ההלוואות/תרומות/הפקדות/הוצאות מקבלות `fund_id`

## שינויים בלוגיקה עסקית (Services)

### שירות חדש: `fundsService`

```typescript
export const fundsService = {
  // קבלת כל הקופות (כולל לא פעילות)
  async getAll(): Promise<Fund[]>
  
  // קבלת קופות פעילות בלבד
  async getActive(): Promise<Fund[]>
  
  // קבלת קופה לפי ID
  async getById(id: string): Promise<Fund | null>
  
  // קבלת קופת ברירת המחדל
  async getDefault(): Promise<Fund>
  
  // יצירת קופה חדשה
  async create(fund: Omit<Fund, 'id' | 'created_at'>): Promise<{ id: string }>
  
  // עדכון קופה
  async update(id: string, data: Partial<Fund>): Promise<void>
  
  // מחיקת קופה (רק אם אין לה שום רשומות, כולל מחוקות)
  async delete(id: string): Promise<void>
  
  // הגדרת קופה כברירת מחדל (פעולה אטומית)
  async setDefault(id: string): Promise<void>
  
  // בדיקה אם קופה בשימוש - יש לה הלוואות/תרומות/הפקדות/הוצאות
  // כולל רשומות שנמחקו (soft delete)
  async hasAnyRecords(id: string): Promise<boolean>
  
  // השבתת קופה (לא מחיקה) - מונעת הלוואות חדשות, ממשיכה לקבל פירעונות
  async deactivate(id: string): Promise<void>
}
```

## השלכות ואתגרים

### ✅ יתרונות
1. **גמישות מלאה** - כל גמ"ח יוכל לנהל כמה קופות שירצה
2. **תאימות לאחור** - גמ"חים עם קופה אחת ימשיכו לעבוד בדיוק אותו דבר
3. **פשטות יחסית** - הוספת שדה אחד בלבד לטבלת הלוואות
4. **הפרדה ברורה** - כל קופה עם יתרה עצמאית

### ⚠️ אתגרים וסיכונים

#### 1. חוקי עסק קריטיים

**מחיקה מול השבתה**:
- מחיקה אפשרית **רק** אם אין שום רשומות בכלל (כולל soft-deleted)
- בדיקה צריכה לכלול: loans, donations, deposits, expenses (כולל `is_deleted = true`)
- קופה מושבתת (`is_active = false`) עם הלוואות פעילות:
  - ✅ ממשיכה לקבל פירעונות
  - ❌ לא מאפשרת הלוואות חדשות
  - מוצגת בדוחות אבל לא בבורר של טופס הלוואה חדשה

**קופת ברירת מחדל**:
- חובה שתהיה תמיד לפחות קופה אחת מסומנת `is_default = true`
- אי אפשר למחוק או להשבית את קופת ברירת המחדל האחרונה
- `fundsService.setDefault(id)` חייבת להיות אטומית:
  ```typescript
  // פסאודו-קוד
  1. החל is_default = false על כל הקופות
  2. החל is_default = true על הקופה החדשה
  3. commitData() - הכל או כלום
  ```

**הלוואות מחזוריות ופירעון אוטומטי**:
- הלוואות שנוצרות אוטומטית מתבנית **חייבות** לרשת את `fund_id` מההלוואה המקורית
- `recurringItemsService` צריך לקבל עדכון בקובץ `src/services/recurringItemsService.ts`
- אזור רגיש - כבר היו באגים של כפילויות (ראו `dailyDuplicatePrevention.test.ts`)

**הלוואות מתוכננות**:
- `expectedFundsCalculator.ts` צריך לחשב לפי קופה
- פונקציה חדשה: `calculateExpectedFunds(fundId?: string)`
- "הלוואות מתוכננות" ב-Dashboard מחושבות לפי קופה

**חריגה מהיתרה**:
- כשהלוואה חדשה > כסף זמין בקופה: **הצג אזהרה, אל תחסום**
- בגמ"ח יש מצבים לגיטימיים (הפקדה צפויה, הבטחה של תורם)
- UI: `<Alert severity="warning">הלוואה זו תגרום לחריגה ביתרת הקופה</Alert>`

**שמירה על עקביות**:
```typescript
// בדיקה אוטומטית (vitest)
it('סכום כל הקופות שווה לסכום הכולל', async () => {
  const allFunds = await fundsService.getAll()
  const fundTotals = await Promise.all(
    allFunds.map(f => statsService.getStatsByFund(f.id))
  )
  const sumOfFunds = fundTotals.reduce((sum, f) => sum + f.activeLoans.total, 0)
  
  const overall = await statsService.getDashboardStats()
  expect(sumOfFunds).toBe(overall.overall.activeLoans.total)
})
```

#### 2. מיגרציה
- **סיכון**: הלוואות קיימות ללא `fund_id`
- **פתרון**: מיגרציה אוטומטית בטעינה ראשונה + בדיקת תקינות

#### 3. וולידציות
- **חובה**: תמיד תהיה לפחות קופה אחת
- **חובה**: לא ניתן למחוק את קופת ברירת המחדל האחרונה
- **חובה**: לא ניתן למחוק קופה עם הלוואות משוייכות

#### 4. UX - חוויית משתמש
- **אתגר**: לא להעמיס על משתמשים עם קופה אחת
- **פתרון**: אם יש רק קופה אחת, להסתיר/להשבית את בורר הקופה בטופס

#### 5. מקומות נוספים שמושפעים

**ייבוא וייצוא אקסל**:
- עמודת `fund_name` בייצוא הלוואות
- בייבוא - תמיכה בעמודת קופה (שם או ID)
- ברירת מחדל: אם אין עמודה, השתמש בקופת ברירת המחדל

**שטרי הלוואה וקבלות**:
- הצגת שם הקופה **אופציונלית** (הגדרה ב-Settings)
- תבנית: "הלוואה מקרן: {{ fund_name }}"

**התאמות בנק** (`BankMatchingPage.tsx`):
- הקופה נגזרת מההלוואה (שדה `fund_id` של ההלוואה)
- **לבדוק**: אם התאמה מתבצעת גם לתרומות/הפקדות - צריך לטפל ב-`fund_id` גם שם

**התראות ולוח שנה**:
- **עדיפות נמוכה בשלב 1**
- בעתיד: סינון התראות לפי קופה
- אפשרות לצפות בלוח שנה רק של קופה מסוימת

**דוחות קיימים** (`reportsService.ts`):
- דוח לווים חייב להציג גם את הקופה
- דוח תנועות כספיות - פילוח לפי קופה

#### 6. תרומות והפקדות
- **✅ החלטה**: אופציה 2 - שיוך תרומות/הפקדות/הוצאות לקופה
- **סיבה**: ללא שיוך אי אפשר לחשב "כסף זמין בקופה" (תרומות + הפקדות − הלוואות)
- **יישום**: הוספת `fund_id` אופציונלי (NOT NULL אחרי מיגרציה) לטבלאות:
  - `donations` 
  - `deposits`
  - `expenses`
- **UI**: השדה מוסתר כשיש רק קופה אחת (כמו בטופס הלוואה)
- **הערה**: פירעונות לא צריכים שדה `fund_id` - הם יורשים אותו מההלוואה

#### 5. העברת כספים בין קופות
- **שאלה פתוחה**: האם צריך אפשרות להעביר כסף מקופה לקופה?
- **אופציה 1**: אין העברות - כל קופה עצמאית לחלוטין

## נספחים

### נספח א': דוגמת קוד למיגרציה (מתוקנת)

```typescript
import { commitData, db } from './database'
import { createBackup } from './fullBackupService'

/**
 * מיגרציה לתמיכה במספר קופות
 * חייבת להיות אידמפוטנטית (בטוחה להרצה חוזרת)
 */
async function migrateFundsSystem() {
  // 1. גיבוי אוטומטי לפני המיגרציה
  try {
    await createBackup('pre-funds-migration')
  } catch (e) {
    logger.error('Failed to create backup before migration:', e)
    throw new Error('לא ניתן להמשיך ללא גיבוי')
  }

  // 2. בדוק אם המיגרציה כבר רצה (אידמפוטנטיות)
  const migrationKey = 'funds_migration_v1_completed'
  if (localStorage.getItem(migrationKey)) {
    logger.info('Funds migration already completed')
    return
  }

  // 3. יצירת קופת ברירת מחדל (אם אין)
  let defaultFund = await fundsService.getDefault().catch(() => null)
  if (!defaultFund) {
    const result = await fundsService.create({
      name: 'קופה ראשית',
      description: 'קופת ברירת המחדל',
      is_default: true,
      is_active: true,
    })
    defaultFund = await fundsService.getById(result.id)
  }

  // 4. שיוך כל הרשומות ללא fund_id (בטרנזקציה מדומה)
  // במקום לולאה - UPDATE אחד לכל טבלה
  const updates = [
    `UPDATE loans SET fund_id = '${defaultFund.id}' WHERE fund_id IS NULL`,
    `UPDATE donations SET fund_id = '${defaultFund.id}' WHERE fund_id IS NULL`,
    `UPDATE deposits SET fund_id = '${defaultFund.id}' WHERE fund_id IS NULL`,
    `UPDATE expenses SET fund_id = '${defaultFund.id}' WHERE fund_id IS NULL`,
  ]

  for (const sql of updates) {
    await db.run(sql)
  }

  // 5. סימון השלמת מיגרציה
  await commitData()
  localStorage.setItem(migrationKey, new Date().toISOString())
  
  logger.info('✅ Funds migration completed successfully')
}

// יש לקרוא לפונקציה הזאת ב-database.ts initialization
```

**הערות חשובות**:
- המיגרציה רצה **רק פעם אחת** (בדיקת `migrationKey`)
- גיבוי אוטומטי **לפני** כל שינוי
- שימוש ב-UPDATE יחיד (לא לולאה) - מהיר וביצועי
- כל הפעולות בתוך טרנזקציה מדומה עם `commitData()`

## שאלות נפוצות (FAQ)

### מה קורה להלוואות קיימות?
כל ההלוואות הקיימות מוקצות אוטומטית לקופת ברירת המחדל במהלך המיגרציה. אפשר להעביר אותן לקופות אחרות אחר כך.

### איך מעבירים הלוואה בין קופות?
בעריכת הלוואה, שינוי הקופה ימחייב הזנת סיבה. השינוי נרשם ב-audit log.

### מה קורה אם מוחקים קופה?
אי אפשר למחוק קופה שיש לה רשומות (הלוואות, תרומות, הפקדות, הוצאות) - גם אם הן נמחקו (soft delete). במקרה כזה, רק השבתה אפשרית.

### האם תרומות משויכות לקופה?
כן. כל תרומה/הפקדה/הוצאה משויכת לקופה. ברירת מחדל: קופת ברירת המחדל.

### מה קורה בפירעון?
הפירעון שייך אוטומטית לאותה קופה של ההלוואה. אין צורך לבחור קופה בפירעון.

### איך מעבירים כסף בין קופות?
בשלב 1 - אין העברות. בעתיד אפשר לרשום הוצאה מקופה A ותרומה לקופה B.

### כמה קופות מומלץ?
2-5 קופות זה אידיאלי. המערכת תומכת ביותר, אבל ממליצים לשמור על פשטות.
